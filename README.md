# 大海战II 视觉复刻原型

后续单机游戏的模块、数据、模型、目录、存档和联机扩展设计见[架构规划](docs/technical/architecture.md)。目录基础整理已经执行；模拟分层、全舰队战斗、存档与联机仍是目标设计，不代表已经实现。

企划、3D原型、美术素材、音乐音效、数值设计、研发、测试与发布的全项目组织方式见[游戏开发目录规范](docs/production/development-structure.md)。

以已收集的老版海战与船厂截图为视觉参考：正交斜俯视海面、小比例舰船、金属仪表式底部控制台、顶部战况、舰桥信息与右下小地图。战斗默认视线约为海面上方 35°，显示侧舷，而非垂直顶视；重置与返回海战恢复同一角度。不是现代舰船展示页。

使用第三方免费授权的大和、俾斯麦、加利福尼亚及约克镇 CV-5 模型。大和为三座三联装、俾斯麦为四座双联装、加利福尼亚为四座三联装，支持航行、独立转炮/俯仰/后坐、弹道与单舰对战。敌舰使用所选舰型的独立实例，船坞、头像和编队预览也按舰型切换；碰撞、影子和艏艉挂点使用对应尺寸。约克镇仅接入外观，没有伪装成战列舰主炮，舰载机战斗未实现，当前不能出击。未匹配舰型仍明确使用大和占位。界面、木板纹理和特效自行制作，没有使用游戏提取素材。

## 运行

Git 只收录白名单中的运行资源：四个转换后的 GLB、舰型/武器/弹药运行 JSON、模型匹配清单、海岸 GeoJSON，以及对应署名、来源和转换记录。原始 STL/3MF/ZIP、截图、手册、研究网页及其余收集资料仍仅保留本地，不签入也不发布。新克隆可直接安装依赖后运行；重新转换模型则需要自行恢复本地原始下载。

安装 Node.js 22.18+ 后，在项目目录运行：

```powershell
npm install
npm run dev
```

打开终端显示的本地网址。当前环境没有全局 Node.js，因此另提供 `start-dev.cmd`：使用本次会话中校验过的便携 Node，不修改系统 PATH。便携运行时若被清理，请安装 Node.js 后使用以上命令。

```powershell
npm test
npm run build
```

F 加速、V 减速，右下 `+ F` / `− V` 按钮按10%调整动力；移除 W / S 推进，保留 A / D 手动转舵。战斗中左键点击锁定海面瞄准点，鼠标移动和本舰移动都不会改变该世界坐标；空格齐射，左键不发射。右键点击设定自动航点，新右键替换旧航点，F/V及手动转舵取消自动航行。小地图左右键同样可以锁定瞄准点/设置远程航点。自动航行按舰船转弯半径预先规划转弯弧和切线接近段，20游戏单位内停车。Ctrl 或 TDA 按钮切换炮塔转动加速。战斗镜头保留固定斜俯视：鼠标移到窗口边缘32像素内滚屏，越靠边越快；开始浏览后停止跟随，C 返回本舰并保留缩放。操作按钮/仪表、按住鼠标、移出窗口、失焦、后台或退出战斗时停止滚屏。浏览限制在战场及周边，不改变瞄准点或航线。滚轮最低缩放0.05，相比默认0.66可缩小13.2倍；镜头高度、裁剪距离和海面覆盖同步调整，避免缩小时海面缺失。宽屏向两侧扩展海域。船厂仍可右键旋转、按 C 切换跟随/自由视角。R仅在船厂重置，战斗中禁用。这不是原版完整手动火控键位。不再提供音效开关及合成炮声。船厂按实际主炮挂点高亮观察及配置弹仓，不能航行或开炮。

### GitHub Pages

公开仓库为 [mayong43111/navyfield](https://github.com/mayong43111/navyfield)，站点地址为 <https://mayong43111.github.io/navyfield/>。本站使用 **GitHub Actions** 部署；推送 `main` 自动运行测试、构建并部署，也可手动触发 Deploy game to GitHub Pages。迁移到其他仓库时，首次需在 Settings → Pages 中选择 GitHub Actions。

工作流按 Pages 提供的项目子路径配置 `GITHUB_PAGES_BASE`。生产包只含代码实际引用的运行资源、署名页面与白名单许可记录，不递归复制 `research` 或整个 `content`。战区右上角提供「署名 / 许可」入口，修改后的大和模型继续遵守 CC BY-SA 4.0，其余三舰为 CC BY 4.0；图形库 MIT 许可和地图公共领域来源随网站保留。

运行 GLB 与 JSON 使用内容适配器下载：支持的 HTTP 服务按 256KiB 分段读取并校验范围、完整长度与版本，避免单个大文件请求长期卡住；不支持 Range 的服务按 HTTP 200 完整响应处理，内联清单直接解析。每个请求有30秒超时，失败明确报错并中止该资源的其他下载。该传输方式不减面、不修改模型几何、游戏数值或许可。

本地验证相同的项目子路径：

```powershell
$env:GITHUB_PAGES_BASE = '/navyfield/'
npm run build
npm run preview
```

### 弹仓与炮控

已移除底部全局菜单，游戏占满窗口。页面通过战区选房、准备出击、港口进船坞、舰艏出港及战斗撤离衔接；圆形黄铜「撤离」按钮放在舰桥指挥官头像上方，不再显示发射计数、战斗计时、炮控菜单和音效开关。主炮使用前后炮组，鼠标左键 / 空格发射，弹仓仪表和射击反馈保持不变。船坞视角仍用 C 切换，R 重置。

已下载并实际阅读[官方完整手册（61 页）](research/manuals/NavyField_Full_Manual.pdf)，来源为 [Steam 官方手册地址](https://steamcdn-a.akamaihd.net/steam/apps/675560/manuals/NavyField_Full_Manual.pdf)。操作说明另见[官网](https://www.navyfield.com/GameInfo/Guide/HowToControl.aspx)。手册截图仅作研究参考，不是自由授权的界面素材。

手册确认的原版规则：

- 第 25–26 页：左侧黄色小表盘是装填表，不是炮塔方位表；数量与武器和舰船配置有关，不能写死四个。两侧黑色大表分别属于 R/T 组，上表为前炮角度，下表为后炮角度；装备鱼雷管时不显示舰炮角度表。
- 第 26 页：舰炮下方是 A/B 弹仓选择及剩余炮弹数。鱼雷对应另一套控件：N 切换窄/宽发射角，H 切换快/慢雷速，不能套用 A/B 舰炮字窗。
- 第 26、52–54 页：中间是舰载机状态/编队操作区，不是主炮信息区。能使用舰载机的配置才显示；其上方小表盘对应飞行编队的准备时间，数量受编队配置影响。Deck/Cargo/Ready 分别表示可同时出发的数量、库存及已准备数量；READY/RETURN/FIND 用于准备、返航和定位飞机。
- 第 26–27 页：右侧为小地图、动力表及 TDA 开关。动力表红区是限时超速，F/V 调节动力；TDA 是炮塔转动加速，Ctrl 切换，并非镜头跟随开关。

采用用户选择的“仅主炮”配置：装填表和弹仓按实际炮座动态生成，每座炮独立装填。大和前二后一，俾斯麦/加利福尼亚前二后二；按实际双联/三联管数筛选官网炮型及扣弹。切换舰型或泊位重建控件与瞄准线，航母显示无可用主炮并禁用弹仓编辑。没有装备 T 组武器和舰载机，战斗中间不显示假飞机面板。右侧动力表显示推进功率，航速使用游戏单位/秒；TDA 实际提高炮塔转速，倍率为 3。

这些是依据手册纠正的布局与读数含义，不是原版大和的精确配装、数值或完整操作复刻。副炮模型目前仅为外观，未接入战斗。超速/引擎兵、完整手动火控、鱼雷及飞机操作尚未实现；动力表的红区仅标示超速区，当前控制限制在常规动力范围。顶部两条细槽分别为舰体耐久与鱼雷防护（手册第 24 页），第二条显示空槽并标明“未配置”，不是推进条或另一条满血量。

A/B 只是弹仓：在船厂选中主炮挂点，分别配置 HE 高爆 / AP 穿甲；改变弹种不会切仓或补充备弹。战斗中点击旋钮或 A/B 数字行选择弹仓，Y 将所选发射炮组统一切换到另一弹仓。每座炮的仓位、弹种、备弹独立；发射实际读取所选弹仓，按炮管数扣弹。每次出击补给至每炮每仓60发，保留配装弹种和所选仓位；这是自研补给规则。R仅在船坞重置，战斗中不能重置或补弹。备弹不足时不自动使用另一仓，并提示原因。

HE 使用暖色弹迹与较宽水花，AP 使用冷色弹迹与较窄水花；毁伤采用下述明确标注的自研换算。切仓不重置当前装填计时，装填采用所装炮型的官网基础秒数（默认九四式普通型17.64秒），没有船员修正；前炮装填时仍可发射已就绪的后炮。保持鼠标自动瞄准，尚未实现原版完整手动火控。

每座主炮显示一条绿色虚线，从实际炮口的几何中心投影出发，长度固定为该炮水平最大射程，只跟随炮塔方向。双联装也使用两炮口中心，不再假定存在第二/中央炮管。炮塔转向时瞄准线仍跟随真实朝向；船厂隐藏瞄准线。

当前单舰战斗有独立敌舰AI、实际弹道命中、耐久损失、击沉与结算；顶部显示本场累计击沉、命中率和实际伤害，不虚构经验系统。小地图实时显示本舰、红色敌舰与瞄准点；底部航速、航向、推进和炮控仪表实时更新。战斗画面左下显示射击、中弹与缺弹提示；船厂保留原航向表。没有联机系统。

### 单舰战斗规则与来源

- 单舰对战只出动准备页所选舰，要求该舰型与当前船坞配装一致且至少有一座主炮具备完整弹药资料；不满足时明确提示并保留准备状态。其他编队舰仍只在准备页配置，不参与本轮战斗。
- 出击前按实际出战配装的最大炮口速度、最大仰角和模型炮口高度上界（含舰体摇摆余量）计算最大射程R。左右各上下两块出生区，共4块，双方区域最近边缘的水平间距为10R；舰体在区内留200单位边缘余量，甲队向右、乙队向左。每48阵位交替放进上下区域，后续页继续增加行，不重叠，列/行间隔300单位。海面覆盖完整战场，小地图展示四块区域、双方舰位、固定瞄准点与航线。仍仅出动所选单舰和一个对等敌舰，没有生成其他编队舰；不会为了快速接敌而缩小用户要求的10倍间隔。
- 敌舰使用相同舰型、耐久和主炮配装作对等对手，但拥有独立导航、炮塔、装填和弹仓；主炮7秒初始整备后开火。AI接近远处目标、保持约270–490世界单位交战距离、转向展开炮组并依据本舰速度预瞄，服从射界、仰角、装填和备弹约束。
- 官网数据实际用于双方舰体耐久、基础装填、最大仰角、普通HE伤害和AP Bonus；兼容官网普通HE名称中的空格及连字符。俾斯麦默认双联 SK C/34，加利福尼亚默认三联 Mark 10，仍按国家与炮位容量校验。不宣称复原所有舰型装备。
- 战斗采用压缩的游戏尺度，不把世界单位写成米、公里或节；目标距离显示游戏单位，航速直接显示单位/秒，导航和预瞄使用同一尺度。统一航速上限14单位/秒，不把史实27.46节套给所有舰型。官网舰体表没有舰长和基础航速字段，未接入引擎、载重和轮机兵的航速计算；船坞显示对应运行外形及游戏舰长，未匹配舰型明确标为大和占位，史实舰长仍未接入。转换舰长只设定资源内部比例，不代表真实米数。
- 自研弹道以九四式普通型官网炮口表值842映射200游戏单位/秒，其他炮按表值比例缩放，重力16游戏单位/秒²；不宣称该比例是原版换算。普通/L/D型水平射程约2500/3004/2048游戏单位，出膛高度另计。点击锁定瞄准点不强行截断距离，实际开火仍检查该炮射程和仰角。各炮瞄准线按该炮水平最大射程固定长度，只跟随炮塔方向，不随鼠标移动、瞄准点距离或炮管仰角伸缩；瞄准线不是本发炮弹预测落点。玩家/AI炮弹及预瞄共用弹道。远射炮弹持续飞至命中或落水，不在15秒凭空删除。转炮仍为0.7弧度/秒（本舰TDA为3倍）。炮弹逐帧按抛物运动积分，用相对运动线段与旋转舰体包围盒连续检测，先命中舰体或海面者生效。包围盒按对应模型尺寸计算，大和保留38×263×16游戏单位，新模型尺寸见转换记录；不是精确三角面穿透模拟。
- 自研散布改为沿射向的均匀面积椭圆：纵向半轴 `28 + 水平距离×0.07`，横向半轴 `14 + 水平距离×0.025`，归一化半径 `sqrt(U)`、角度 `2πV`，每根炮管独立采样。400单位距离约为112×48单位的散布区，落水及近远偏差明显；不是已验证的Navy Field散布。极限射程的落点截在该炮实际可达范围内，避免随机偏移导致开火报错；并未增加额外的概率扣血。
- 自研伤害：HE能量使用官网普通HE伤害；AP能量为 `HE×(1+AP Bonus×0.1)`，**AP Bonus不是直接扣血**。最终伤害为 `round(能量/(1+护甲阻力))`；HE阻力 `厚度/100`，AP阻力 `厚度/(100×(1+AP Bonus))`。舷侧/甲板厚度目前为0，不把官网护甲系数当成已安装装甲。没有距离穿深、过穿、装甲耗损、船员SD或维修模拟。
- 船坞可配置防雷装甲0–10档，每泊位独立，默认1档，0档卸除。容量按对应国家官网护甲表的Bulge系数乘`档位×50`自研换算；不是原版厚度/防护公式。日本NVNC系数100，1档5000、3档15000。出击将容量存入双方独立战斗状态，顶部防雷条显示当前/最大防护值；HE/AP主炮不消耗该值，不把它冒充万能护盾。本轮未加入鱼雷武器或鱼雷伤害，遵循用户选择的“先配装与防护值”范围。
- 命中只计算实际击中仍存活目标的炮弹，伤害不超过剩余耐久；同时最后一击可判双方沉没。命中出现短促白热闪光、受重力影响的飞散火花和烟团，高爆命中留下随舰体移动的局部火焰。燃烧仅是视觉效果，不额外扣血。舰体归零停止航行与开火，爆炸、侧倾、艏艉俯仰、泡沫扩散和水花随后出现，约18秒完全下沉；5秒后显示结算，特效继续播放。结算后不会再扣血。特效最多500粒、8处火点，撤离全部清理。背景页面暂停模拟，下一场重新建立战斗。
- 战斗支持1280×720、1600×900、1920×1080等16:9窗口，横向扩展正交视野而非拉伸画面；宽屏字体和海图尺寸适度增长，舰桥按钮与海图保持间距。其他比例仍适配窗口，未强制黑边或锁定分辨率。
- `D:\FleetMission\DATA\zh-cn` 的Gunset／Projectile／Armor／Frame表只检查了文件头，均非可直接读取的文本，未解密、未提取客户端代码或资源，也未据此编造数值。社区 [NavyTPB资料索引](https://github.com/NavyTPB/Navyfield)只提供攻略／计算器链接，未提供可核实完整伤害／散布算法。已使用的 [Three.js](https://github.com/mrdoob/three.js) 为MIT开源图形基础；未复制来源不明的反编译服务端代码。上述缺口由本项目自行实现，不称为原版还原。

战斗视图使用状态条、黑色角度表与黄铜色装填表、A/B 分隔字窗。小地图框线投影当前镜头所见的海面范围。海面使用低对比度灰蓝噪声，舰船甲板使用自行生成的木板纹理，烟气、尾流和水花使用自行绘制的透明纹理；这些精细样式只作用于战斗视图，船厂保留原炮控布局。
