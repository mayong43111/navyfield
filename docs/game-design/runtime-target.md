# 十二舰目标版：运行接入与维护

当前应用启用 `target-v1.3.0`、schema 3 与操作修订1。本文说明已接入的玩法，不把离线设计、模型候选或未来功能当作运行成果。

## 1. 数据与模块边界

- 唯一可编辑数值：[design-data/source](../../design-data/source/README.md) 中的 CSV。舰体、装甲、武器、弹种、炮位控制、武器模式、自动组、房间与差异化资料在此维护。
- 统一舰船运行数值目录：[content/data/ships](../../content/data/ships/)。[target.json](../../content/data/ships/target.json) 是导出产物，不手改；不从模型炮管数量或旧官网数值反灌规则。
- [export-runtime.py](../../tools/balance/export-runtime.py) 导出10张数值源表并写入输入哈希；模型研究与实验表不进入运行数值。`models.csv` 的审计更新会改变离线完整输入哈希，但不会改变运行数值哈希。
- [target-content.ts](../../src/domain/target-content.ts) 定义并校验内容合同；[内容适配器](../../src/adapters/content/target-content.ts) 加载 JSON。
- [目标港口适配器](../../src/adapters/local/target-port-content.ts) 提供12舰泊位和固定舰装；[目标建战适配器](../../src/adapters/local/target-battle-config.ts) 从数值内容建立战斗，不依赖 Three 或真实炮座节点。
- [TargetBattleSimulation](../../src/simulation/target-battle.ts) 组织固定30Hz模拟；`target-weapons`、`target-aircraft`、`target-physics` 分别处理炮组状态、航空与弹道/毁伤。所有战斗随机数来自独立种子。
- [LocalBattleSession](../../src/adapters/local/battle-session.ts) 按 `rulesVersion` 分派内核。旧 `single-ship-v1` 保留兼容与回归，不是当前应用规则。
- [runtime.ts](../../src/app/runtime.ts) 只组合内容、港口、会话、输入、界面与表现；[武器面板](../../src/ui/target-weapons.ts) 提交命令并显示只读观察，不能修改数值真值。
- 模型身份/来源/许可映射独立保留于[模型清单](../../content/manifests/ship-model-catalog.json) 的 `targetModels`。数值船体尺寸与炮位合同决定碰撞和火力，视觉资源不决定有效管数。

从项目根目录用工作区虚拟环境运行：

```sh
.venv/bin/python tools/balance/run.py --check
.venv/bin/python tools/balance/export-runtime.py
.venv/bin/python tools/balance/export-runtime.py --verify
.venv/bin/python tools/balance/run.py
.venv/bin/python tools/balance/run.py --verify
.venv/bin/python tools/balance/controls.py
.venv/bin/python tools/balance/controls.py --verify
.venv/bin/python -m unittest discover -s tests/balance -p 'test_*.py'
npm test
npm run build
```

虚拟环境可以在仓库外，按实际位置调整 Python 路径。CSV 修改后重生成运行 JSON、试算与回放；不维护第二份手写舰船数值。

## 3. 武器操作与状态

1. 在港口选择舰艇；舰装固定来自 CSV，只能为主炮选择出击初始 AP/HE。航母不伪造主炮或主炮弹仓。
2. 战斗左下选择主武器、第二武器/副炮、小口径防空。手动舰炮 C 按全部→前→后→全部循环，选择的是当前物理炮组的前后炮座集合，不切武器位置，也不是逐座轮换。前半（奇数时含中间座）为前炮组，后半为后炮组，沿用现有 rear 编号约定。面板独立选单座时回到全部炮组，C 切换则退出单座选择；换武器位置默认全部。炮位不等于自动控制，副炮也不是天然自动。
3. 手动舰炮：左键将点击位置换算为各炮座的海图方位与仰角并锁定、空格齐射；渐次模式按住空格或面板按钮，松开/失焦停止。舰船平移和转向后仍保持该世界发射方向与仰角，不持续追踪原点击坐标；海图落点指示随发射起点平移。再次左键重新计算射击角度，选组或用途切换后需重新瞄准。舰体遮挡、射程、用途与备弹校验仍有效，不绕过射界限制。鱼雷保持海图发射方位，航空保留任务指令。
4. Z 按当前手动舰炮开放用途及弹种策略循环：普通炮 HE→AP→HE；弗莱彻对舰 HE→对舰 AP→对空 HE→对舰 HE。不支持的模式/弹种不会加入循环，无第三种 AA 库存；面板切用途仍恢复记忆的对舰弹种。X 切齐射/渐次。C/Z/X 先取消按住射击，Z 后重新预瞄。Y 不再切 AP/HE；鱼雷、航空、自动组不响应 C/Z/X。逐管共享备弹与装填，切换等待按炮组 CSV 配置（弗莱彻换弹/两用用途为2.5s，普通对舰炮当前为0s），不补弹、不重置装填；每次出击初整备7s。齐射必须所有选中炮管准备且有弹，不能自动降为部分齐射。
5. 弗莱彻原4管主炮可以切手动对空：固定HE，设定高度后左键预瞄，或用按钮预瞄最近敌机**当前位置**，玩家自行给提前量；30u定时球爆，不是自动追踪必中。返回对舰恢复记忆弹种，库存与装填继续共享。
6. 自动副炮和20/40级小AA只提供启停，不能通过空格手动开火。启停不恢复备弹/装填；重新启用需要重新锁定。BB没有另补未批准的手动重防空。
7. BB近防副炮维持减装方案：加利福尼亚/俾斯麦/大和全舰4/8/4管，分舷有效2/4/2；127/152射程600/550u，较大散布、锁定和转炮约束。小AA射程1200/600u，命中概率维持削弱20%的设定，不保证阻止投弹。
8. 阳炎/最上选择第二武器后预瞄并空格发射鱼雷；航母主武器预瞄并空格出动。鱼雷独立弹池；航空使用可用飞机/损失状态，模拟出动、投弹、击落、返航回收，不套主炮逐管库存界面。

电脑手动武器采用入门瞄准：每2秒采样一次目标状态，1.5秒后才能使用该观测，舰炮只采用65%的预测提前量；每次观测得到固定误差点，最大误差半径为 `90u + 射程 × 0.04`，不会逐帧重新抽取直到命中。开火另等1.2秒，整轮装填后仍有该额外迟疑。误差使用独立种子流，保持固定步回放一致。自动副炮/小AA与玩家武器的原数值不变；航空任务保持现有追击规则。本调整降低电脑手动炮/鱼雷的瞄准优势，不宣称已完成真人试玩平衡。

战斗底部保留航向/动力仪表，并由[目标仪表模块](../../src/ui/target-instruments.ts)显示实际主武器的逐座装填进度、共享备弹及前后主炮仰角；航母显示可用飞机，不套用旧46厘米主炮或甲乙弹仓。武器控制面板放在仪表上方，避免遮住仪表。

海图四边的移屏带扩大为72像素（小视口不超过边长的一半），向边界渐进加速。鼠标从边缘离开网页时保持最后的移屏方向；回到内部停止移屏，点击/拖动、控制面板、窗口失焦、页面隐藏、对话框、离开战斗及Home回舰都会清除移屏意图。

每次新出击按 CSV 重新整备；退出保留港口兼容状态供显示，但不把上一场主炮余弹当下一场目标版弹池。旧A/B只是内部兼容字段，目标界面隐藏乙仓、标注初始弹种，不存在两套独立可切换库存。详细状态约束见[操作规则](weapon-controls.md)。

## 4. 房间与当前范围

- 当前单机1对1，主流程使用当前港口泊位舰；高级编队使用所选舰，对手均为同型独立敌舰。其他编队舰不参战，不宣称舰队战斗。
- `duel` 地图10000×6000u、出生区1200×1800u、中心间隔4400u。每舰按自己的初速度/加速度/最大航速运动，不再统一14u/s或旧10R间隔。
- 准备预算30s只是建议，不强制自动开局。出击按钮启动3s倒计时；主流程准备时冻结当前舰/配装与随机种子的建战配置，确认后复用，不偷偷重新抽签。取消、离开、打开指南、页面转后台或销毁时清除倒计时。高级编队仍保留准备/阵位编辑与出击条件复核。
- 战斗上限600s，初装填7s；具体最早交手取决于射程、出生位置、运动和瞄准，见[房间试算](../../design-data/reports/target-v1/rooms.csv)。单位u不是米、公里或节，装甲mm也为抽象数值。
- 未实现：全舰队、占点、修理指令、存档、联机和BB重防空扩展。离线报告中有修理/占点设计，不代表运行内核已接入。

## 5. 游戏旅程与界面验收

| 位置 | 玩家任务与实现边界 |
| --- | --- |
| 载入 | 独立整备画面显示资源进度；失败显示真实原因与重试，不伪装已进入游戏。 |
| 首页 `home` | 舰队司令部、单机模式、十二舰说明、操作指南与制作署名入口。 |
| 港口 `yard` | 泊位名册选择当前舰、查看定位与真实配装、初始AP/HE。重置弹仓仅恢复港口兼容观察；每次目标出击自动重新整备弹池。 |
| 准备 `briefing` | 当前舰艇、实际炮位/备弹、初始弹种、出生速度、地图尺度、规则版本、时限与操作摘要。这里只建立配置，不开始模拟。 |
| 战斗 `battle` | 现有舰炮/鱼雷/航空/自动组与导航内核不改。指南和撤离确认暂停本地会话；取消撤离继续同一会话。 |
| 战果 `results` | 会话胜利/失败/平局观察触发，立即暂停终局；显示真实击沉、命中/发射、伤害、耐久与固定30Hz用时，无虚构货币/经验。平局区分双方沉没与到达时限。 |
| 归港 / 再战 | 归港结束旧会话、接收上一场主炮余弹显示。再战新建配置与会话，复用所选舰/部署，恢复舰体和目标版弹池，不继承终局统计。无刷新后的持久进度。 |
| 高级战区 `warzone/prepare` | 原战史地图、本地房间、阵型与名册保留。标签明确非多人大厅；地点是编队分类，不改变实际统一演习地图。 |

导航始终显示位置，主要交互使用语义按钮；独立页面标题与对话框有焦点管理，倒计时为可取消的状态播报。深海蓝/黄铜强调主行动，准备与战果采用可滚动卡片；窄屏港口改为垂直整备布局，不强制左右面板挤压舰艇。战斗仍推荐桌面键鼠，未新增触屏操舰系统。

## 6. 验证边界

Node测试覆盖12舰出击/退出、逐管状态、自动组、手动两用、鱼雷、航空、内容加载及旧内核兼容；Python测试与逐字节验证覆盖数值/操作报告，生产构建校验TypeScript和打包资源。

本轮按用户要求将真实浏览器验收后置；此前本地开发服务器HTTP响应正常，但隔离Chromium因缺少 `libglib-2.0.so.0` 无法启动，环境也没有可用现成浏览器。没有通过安装系统组件绕过限制。因此不能把自动测试和构建通过称作实际3D画面/交互验收通过；仍需在正常浏览器检查显示布局、炮塔/飞机表现、准备倒计时、输入焦点和出击撤离流程。
