# 游戏程序

已落实[架构规划](../docs/technical/architecture.md)的单舰模拟边界，并接入12舰目标内容与内核；完整运行范围和CSV维护见[目标接入说明](../docs/game-design/runtime-target.md)，不宣称全架构完成。

- `main.ts` / `app`：启动、资源加载、进度/错误/重试。`controller.ts` 无环境依赖，管理页面/会话生命周期和指令路由；`runtime.ts` 只组合适配器、视图、界面、输入及页面时钟。
- `domain`：不同用途的 ID、冻结战斗配置、命令、事件、数值状态、只读观察和会话契约。
- `simulation`：导航、航线、炮控、弹仓、AI、弹道、连续碰撞、毁伤、沉没与结算。仅数值/领域依赖；固定 30Hz，战斗独立种子随机数。
- `adapters/local`：目标港口/建战适配器读取统一CSV导出内容，不依赖视觉模型节点；旧资料/模型建战适配器仅保留兼容。`LocalBattleSession` 按规则版本分派内核，排队命令、推进固定步、发布冻结观察与稳定 ID 事件。
- `game`：`PortController` 独占港口舰艇/配装状态，接收港口命令并发布冻结观察；战斗退出时显式接收弹仓，而非每帧复制。另保留历史战区与既有准备状态。
- `input`：键盘和画布/海图指针映射为命令，失焦/后台清理；不处理模型或配装。
- `presentation`：`battle-view.ts` 只管理 Three 场景、海面、镜头、模型姿态与数值投影；`environment`、`battle-effects` 分别处理环境与炮弹/命中/火焰。旧跨层屏幕协调器已经删除。
- `ui`：弹仓/配装/泊位控制器、仪表/结算、战术图、投影标签及准备页；操作提交命令，显示只读观察，不修改港口或模拟状态。

顶层 `combat`、`navigation`、`ammunition`、`camera`、`lobby-state` 等保留旧导出路径，保证既有调用与回归测试兼容。`ships`、`yamato`、`original-data`、`lobby-art`、`ui.ts` 暂留原位置；它们不是纯模拟依赖。

已完成目标内容导出、独立于模型的数值炮位合同、12舰主炮/鱼雷/航空、自动近防/小AA与手动两用操作。舰船运行数值统一在 `content/data/ships/target.json`，`target-*` 模块与旧内核按版本分离。模型清单负责视觉映射，8舰缺模型显示定位框，不复用大和。

尚未完成：全舰队、占点、修理、存档/回放、联机和BB重防空扩展。当前仍只选一艘本舰与一艘同型敌舰；旧内核保留兼容测试，不是应用实际规则。更换视觉模型/镜头/特效不改变已冻结模拟，也不参与目标建战数值。

后台明确暂停；可见页面卡顿补齐全部模拟步，不丢弃炮弹时间。特效使用自己的随机源，视觉摇摆不参与碰撞或炮口计算。
